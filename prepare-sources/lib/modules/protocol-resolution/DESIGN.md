# protocol-resolution — design (grill-with-docs)

Pre-implementation design for RHIDP-15838. **Implement against this document**; keep `README.md` as the post-implementation module guide.

Related: `docs/source-preparation-design-decisions.md` §4, §11.

## Language

**Protocol reference:**
A `package.json` or `yarn.lock` dependency specifier using `workspace:^`, `workspace:*`, `workspace:~`, or `backstage:^`.
_Avoid_: monorepo ref (too vague).

**Surviving local package:**
A workspace package whose directory still exists on disk after `plugin-removal`. Keeps `workspace:^` references in `package.json` and `yarn.lock` so `rhdh-cli` can resolve them during re-export.
_Avoid_: exported plugin (export is a later step).

**Scrubbed package:**
A package listed in `manifest.json` whose source directory was removed by `plugin-removal`. Protocol references to scrubbed packages are resolved to concrete npm semver ranges.
_Avoid_: deleted package (ambiguous with `package-cleanup` lockfile deletion).

**Version map:**
`Map<packageName, exactVersion>` built from `manifest.json` and `backstage-manifest.json` (generated before scrubbing). Authoritative for resolving protocol references.
_Avoid_: version manifest (collides with manifest.json naming).

**Type-shims package:**
`@internal/type-shims` at `packages/type-shims/` — aggregates host deps (`react`, etc.) and `@types/*` from scrubbed packages needed by surviving code. Pre-wired in `yarn.lock` as `linkType: soft`.
_Avoid_: stub package (old per-package approach).

## Relationships

- **protocol-resolution** runs after `generate-manifests`, `plugin-removal`, and `file-cleanup`
- Reads `manifest.json` (+ `backstage-manifest.json` when present) written before scrubbing
- Equivalent to `update-workspace.js --update` plus the `createTypeShimsPackage` portion of `--delete` (physical deletion already done by `plugin-removal`; lockfile entry deletion is `package-cleanup`)
- `package-cleanup` runs next and removes scrubbed package lockfile blocks

## Resolved decisions

### 1. Scope = `--update` + type-shims only

Implement protocol reference resolution in `package.json` and `yarn.lock`, plus `packages/type-shims/` creation. Do **not** implement `--delete` lockfile scrubbing or `--remove-patches` — those are `package-cleanup`.

### 2. Preserve `workspace:^` for surviving local packages

Match `replaceWorkspaceReferences`: if `findPackageVersion(name)` finds a local `package.json`, skip conversion in `package.json`. In `yarn.lock`, local packages get combined-key normalization only — no npm block replacement.

### 3. Manifest-driven version map

Build version map from workspace + backstage manifests on disk. No `--version-map` CLI flag; manifests are the sole source (generated by `generate-manifests` in the same pipeline run).

### 4. npm metadata via `fetch`

When creating missing resolution blocks, fetch npm registry metadata with `fetch` (retries for transient errors). Prefer backstage-manifest entries when available.

### 5. `yarn.lock` processed once per workspace

Process all `package.json` files but run the full `yarn.lock` transformation only once (first file triggers it), matching the original single-pass semantics.

### 6. Type-shims timing

Create type-shims after `yarn.lock` rewrite. Analyze scrubbed packages via manifest entries whose `path` directory no longer exists. Skip creation when nothing is needed.

## Algorithm (implementation contract)

1. Load `manifest.json`; load `backstage-manifest.json` if present.
2. Build version map (workspace packages first, backstage packages fill gaps).
3. Discover all workspace `package.json` files (same ignore dirs as `generate-manifests`).
4. For each `package.json`: replace protocol refs in dependency sections; write if changed.
5. Once: parse `yarn.lock` via shared `yarn-lock-parser`, mutate the `Lockfile` structure, serialize back (delete stale/non-local workspace blocks, convert dep refs, recreate npm blocks, dangling-dep passes, enrich specifiers).
6. Create `packages/type-shims/` when needed; update root `package.json` workspaces and `tsconfig.json` references; pre-wire lockfile entry.
7. Throw on unrecoverable yarn.lock inconsistencies or npm metadata failures for required blocks.

## Error handling

- Missing `manifest.json` → throw (required input).
- Missing `yarn.lock` at workspace root → throw.
- `createMissingResolutionBlocks` npm fetch failures or soft-link inconsistencies → throw with package list.

## Pipeline position

After `file-cleanup`, before `package-cleanup`.
